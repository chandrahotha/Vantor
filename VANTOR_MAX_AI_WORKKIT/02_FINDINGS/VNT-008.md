# VNT-008 — Webhook delivery is synchronous and has no durable retry worker.

> **Source of truth:** Current VANTOR archive re-audit

## Classification

- **Severity:** High
- **Status:** Verified
- **Confidence:** High
- **Category:** Integration reliability

## Location

`backend/app/services/integration.py:74-133`

## Evidence

`fanout()` performs `httpx.post()` directly in the API call, with one attempt per endpoint. Failed deliveries are recorded but there is no code here that consumes `MAX_ATTEMPTS` or retries failed/deferred deliveries.

## Impact

API latency is coupled to partner availability, failed events need manual recovery, and transient errors can permanently lose delivery unless an operator replays them.

## Required remediation

Persist an event/outbox record in the same transaction as the business change; enqueue delivery asynchronously; implement exponential backoff, jitter, max attempts, DLQ, replay, per-endpoint circuit breakers, and idempotency keys.

## Required invariant / acceptance

The remediation must preserve tenant isolation, auditability, authorization correctness and deterministic behavior.

## Required tests

Slow endpoint; timeout; 429; 500; network error; process restart; duplicate delivery; replay from DLQ.
