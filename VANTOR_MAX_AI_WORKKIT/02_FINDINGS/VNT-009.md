# VNT-009 — Uploaded documents default to container-local filesystem storage.

> **Source of truth:** Current VANTOR archive re-audit

## Classification

- **Severity:** High
- **Status:** Verified
- **Confidence:** High
- **Category:** Persistence

## Location

`backend/app/services/document.py:72-82; backend/app/routers/documents.py:80-85,144-159; docker-compose.yml:95-110`

## Evidence

The document service defaults `UPLOAD_DIR` to `uploads`. The Docker backend has no uploads volume. MinIO exists only as an optional Compose profile and is not used by the document service.

## Impact

Container replacement can leave database rows pointing at missing document bytes. Horizontal replicas cannot reliably share local uploads.

## Required remediation

Use S3-compatible object storage as the production default, store immutable object keys, include content hash/version metadata, use server-side encryption, lifecycle rules, object retention where required, signed URLs or streaming proxy, and a repair/reconciliation job.

## Required invariant / acceptance

The remediation must preserve tenant isolation, auditability, authorization correctness and deterministic behavior.

## Required tests

Container recreation; two backend replicas; object missing; object tampered; restore from backup.
