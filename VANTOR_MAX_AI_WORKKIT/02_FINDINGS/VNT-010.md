# VNT-010 — Upload endpoint reads the entire file into memory before enforcing the configured size limit.

> **Source of truth:** Current VANTOR archive re-audit

## Classification

- **Severity:** High
- **Status:** Verified
- **Confidence:** High
- **Category:** Upload reliability / security

## Location

`backend/app/routers/documents.py:49-72`

## Evidence

`data = await file.read()` at line 63 reads the full multipart payload, and `check_size(len(data))` runs only afterward at lines 65-68.

## Impact

A client can send a payload much larger than `MAX_UPLOAD_MB` and consume application memory before the application-level limit is checked.

## Required remediation

Enforce request body limits at the edge and stream uploads to temporary/object storage while counting bytes, aborting as soon as the configured maximum is exceeded. Hash while streaming.

## Required invariant / acceptance

The remediation must preserve tenant isolation, auditability, authorization correctness and deterministic behavior.

## Required tests

51MB/500MB payload against 50MB limit; slow upload; multiple concurrent oversized uploads; interrupted upload cleanup.
