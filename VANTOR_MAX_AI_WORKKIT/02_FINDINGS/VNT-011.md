# VNT-011 — DOCX/XLSX ZIP parsing lacks archive bomb/resource limits.

> **Source of truth:** Current VANTOR archive re-audit

## Classification

- **Severity:** High
- **Status:** Strong static finding
- **Confidence:** High
- **Category:** Document pipeline security

## Location

`backend/app/services/extract.py:92-146`

## Evidence

`zipfile.ZipFile(io.BytesIO(data))` opens the archive and reads XML parts. There are no explicit limits on member count, uncompressed size, compression ratio, nested depth, or XML size.

## Impact

A crafted compressed document can consume disproportionate CPU/memory while staying below the raw upload size limit.

## Required remediation

Inspect central-directory metadata before extraction; enforce member count, per-member size, total uncompressed bytes, compression ratio, path safety, and XML parser resource limits. Reject unsupported relationships and external entity behaviors.

## Required invariant / acceptance

The remediation must preserve tenant isolation, auditability, authorization correctness and deterministic behavior.

## Required tests

ZIP bomb fixture; 10k members; oversized member; highly compressed payload; malformed central directory.
