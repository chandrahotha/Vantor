# VNT-012 — File type validation is based on a very small magic-byte sniff and extension conventions.

> **Source of truth:** Current VANTOR archive re-audit

## Classification

- **Severity:** Medium-High
- **Status:** Verified
- **Confidence:** High
- **Category:** Document validation

## Location

`backend/app/services/document.py:30-58; backend/app/routers/documents.py:60-71`

## Evidence

`sniff_kind()` checks only the first 16 bytes for a small set of signatures. For DOCX/XLSX it identifies any ZIP as `zip`; the extension controls later parser selection. TIFF is accepted by extension without magic-byte validation.

## Impact

Malformed or polyglot inputs can pass initial validation and reach parsers not designed for the actual content.

## Required remediation

Use a content-type detection library or strict signature validation per supported format, verify ZIP package contents before classifying DOCX/XLSX, validate TIFF/JPEG/PNG structure, and quarantine on mismatch.

## Required invariant / acceptance

The remediation must preserve tenant isolation, auditability, authorization correctness and deterministic behavior.

## Required tests

ZIP renamed to DOCX with missing required parts; TIFF text; polyglot; invalid JPEG header; extension mismatch.
