# VNT-024 — Contract expiry roll uses server date and is callable through a broad write endpoint.

> **Source of truth:** Current VANTOR archive re-audit

## Classification

- **Severity:** Medium
- **Status:** Verified
- **Confidence:** High
- **Category:** Operations / time

## Location

`backend/app/routers/contracts.py:191-212`

## Evidence

`roll_expiry()` uses `date.today()` at line 194 and is accessible with `_write(actor)` at line 193. Scheduler calls it through a service token but the public route is not worker-only.

## Impact

Expiry timing can vary by server locale, and ordinary write-role users can trigger lifecycle batch changes.

## Required remediation

Use tenant/business timezone as the source for the effective date, expose a worker-only command protected by service identity and job authorization, make the job idempotent, and emit exact transition events.

## Required invariant / acceptance

The remediation must preserve tenant isolation, auditability, authorization correctness and deterministic behavior.

## Required tests

Timezone boundary around midnight; duplicate job; worker identity; manual role denied; DST transitions.
