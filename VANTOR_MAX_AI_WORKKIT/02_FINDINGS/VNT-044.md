# VNT-044 — Worker jobs depend on a manually provisioned service token and are not self-bootstrapping.

> **Source of truth:** Current VANTOR archive re-audit

## Classification

- **Severity:** Medium
- **Status:** Verified
- **Confidence:** High
- **Category:** Async jobs

## Location

`worker/jobs.py:17-39; worker/beat.py:19-34; .env.example SERVICE_API_TOKEN`

## Evidence

`jobs._token()` fails if `SERVICE_API_TOKEN` is absent. `beat.py` schedules jobs, but `.env.example` leaves the token empty.

## Impact

A nominally deployed scheduler can run while all jobs fail because service authentication was never provisioned.

## Required remediation

Use Keycloak client credentials or workload identity to obtain service tokens dynamically; store only client credentials in secret management, validate job readiness at startup, and expose job success/failure metrics.

## Required invariant / acceptance

The remediation must preserve tenant isolation, auditability, authorization correctness and deterministic behavior.

## Required tests

Fresh deployment; token rotation; token expiry; job retry; scheduler and worker mismatch.
