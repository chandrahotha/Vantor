# Re-Audit - 2026-10-02

A from-scratch adversarial audit of the running system (not a review of documentation claims),
cross-checked against the existing [`MASTER_FINDINGS.md`](MASTER_FINDINGS.md) (VNT-001…045) and
[`BUGS.md`](../BUGS.md) registers. Every finding below was either reproduced live against a real
PostgreSQL instance and the actual application, or confirmed by direct source inspection with
file:line citations. This document supersedes `BUGS.md` and `SCORECARD.md` as the current source
of truth for defect/risk status as of this date; those two files are being rewritten separately to
remove the textual corruption found in them (see §6).

Severity: **P0** security/data-loss/system-integrity blocker · **P1** production deployment
blocker · **P2** major functional defect · **P3** quality/maintainability · **P4** cosmetic.

## 5. Release decision

**DEPLOYABLE WITH SPECIFIC CONDITIONS.**

Conditions, in priority order:
1. Deploy only via `docker compose up` (now that RA-001/RA-002 are fixed and live-verified) or the
   documented single-container path with its stated single-tenant caveat - never with a hand-rolled
   deployment that skips the new `migrate` step or reuses the owner role for the app connection.
2. RA-010 (frontend e2e CI) is now fixed - confirm the next CI run actually passes Playwright
   end-to-end before trusting the accessibility/visual-regression suite as a live gate; it has
   never run successfully in CI before, so this fix should be watched on its first real run.
3. Treat RA-005 (AI evidence fidelity) as a known limitation of the Copilot feature specifically,
   not of the platform generally - do not expose the AI gateway to untrusted external users until
   addressed, since the HITL gate on mutations limits blast radius but the *advisory* answers it
   gives are not fully trustworthy against adversarial-but-legitimate tenant-supplied data.
4. Complete the documentation consistency pass (status labels, orphaned docs) before using the
   `docs/` tree as an external-facing claim of what's implemented - several individual docs
   currently understate what the code actually does, which is a safer failure mode than
   overstating it, but still worth fixing.

Not a blocker, but notable: this audit found and fixed the kind of defect (RA-001) that is
specifically the reason earlier claims of "production-grade" anywhere in this repo's own history
should have been read skeptically - the gap was invisible to every existing test, every prior
internal audit pass, and the CI pipeline, because none of them exercised the actual database role
the application connects as. The fix is live-proven, not just code-reviewed, and ships with a
regression test designed so that removing the fix makes the test fail, not just lowers coverage.
