# VNT-002 - Direct PO approval route is broader than the approval decision authority.

> **Source of truth:** Current VANTOR archive re-audit

## Classification

- **Severity:** High
- **Status:** Verified
- **Confidence:** High
- **Category:** Authorization / financial control

## Location

`backend/app/routers/purchase.py:32,326-363`

## Evidence

`WRITE_ROLES` includes Buyer and Finance Reviewer at line 32. `approve_po()` uses `_write(actor)` at the start and checks pending approval/budget, but does not call `decide_approval()` or enforce `APPROVER_ROLES` before changing PO state.

## Impact

A role intended only for document editing may be able to approve a PO through the direct endpoint, bypassing the canonical approval authority rules.

## Required remediation

Remove direct PO state approval or make it a thin call into the shared approval service. Enforce tier-specific authority, SoD, sequence, spend limit, and approval-row state in one service.

## Required invariant / acceptance

The remediation must preserve tenant isolation, auditability, authorization correctness and deterministic behavior.

## Required tests

For every role × tier × amount combination, assert allowed/denied. Test direct endpoint and approval endpoint produce identical authorization decisions.

Before editing, re-open the cited code and verify that the current source still matches this finding. If code has moved, update the evidence location before proceeding. Do not implement a workaround that leaves two competing code paths enforcing different versions of the same rule.
