# VNT-004 - Budget approval is race-prone.

> **Source of truth:** Current VANTOR archive re-audit

## Classification

- **Severity:** High
- **Status:** Verified
- **Confidence:** High
- **Category:** Concurrency

## Location

`backend/app/routers/purchase.py:326-363; backend/app/routers/catalog.py:60-100`

## Evidence

Budget state is read and compared before PO approval. `check_budget()` computes committed amount and compares it with the ceiling, but there is no row lock, conditional atomic UPDATE, reservation ledger, advisory lock, or serializable transaction around the read/check/write sequence.

## Impact

Two concurrent approvals can both pass against the same remaining budget and over-commit a budget.

## Required remediation

Use a dedicated budget-period row locked `FOR UPDATE`, or an atomic conditional reservation update. Commit the reservation and PO approval in one transaction. Define release/rollback rules for cancellation and rejection.

## Required invariant / acceptance

The remediation must preserve tenant isolation, auditability, authorization correctness and deterministic behavior.

## Required tests

Two concurrent approvals that individually fit but jointly exceed budget; exact ceiling; rejection rollback; cancellation release; cross-category budgets.
