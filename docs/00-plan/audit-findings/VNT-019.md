# VNT-019 — RFQ award has a concurrency window around the unique Award constraint.

> **Source of truth:** Current VANTOR archive re-audit

## Classification

- **Severity:** Medium-High
- **Status:** Verified
- **Confidence:** High
- **Category:** Concurrency / sourcing

## Location

`backend/app/routers/sourcing.py:260-323`

## Evidence

The route checks for an existing Award before inserting a new one at lines 266-269, but two concurrent requests can both observe no existing row before one insert wins. The insert is not wrapped in a conflict-to-409 handler in this path.

## Impact

Concurrent award attempts can surface a database integrity error as a 500 rather than a deterministic conflict.

## Required remediation

Use a unique constraint as the final authority and catch `IntegrityError` to return 409. Lock the RFQ row for the decision and perform award/status/loser updates in one transaction.

## Required invariant / acceptance

The remediation must preserve tenant isolation, auditability, authorization correctness and deterministic behavior.

## Required tests

Concurrent award of different quotes; concurrent award of same quote; retry after 409.
