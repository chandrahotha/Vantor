# VNT-023 — E-sign path records provider/envelope identifiers but does not verify external signature state.

> **Source of truth:** Current VANTOR archive re-audit

## Classification

- **Severity:** Medium-High
- **Status:** Verified
- **Confidence:** High
- **Category:** Contracts / e-sign

## Location

`backend/app/routers/contracts.py:221-249`

## Evidence

The route requires non-empty provider/envelope_id, hashes a snapshot, stores `ContractSignature`, and commits. There is no provider status verification or webhook callback validation in this path.

## Impact

A signature record can exist without cryptographic/provider evidence that the envelope was actually completed.

## Required remediation

Introduce provider adapters with webhook signature verification, envelope status polling, signer identity mapping, document-version locking, and completion timestamp. Treat local record as pending until provider confirmation.

## Required invariant / acceptance

The remediation must preserve tenant isolation, auditability, authorization correctness and deterministic behavior.

## Required tests

Pending envelope; provider callback success/failure; forged webhook; changed document; multiple signers; expired envelope.
