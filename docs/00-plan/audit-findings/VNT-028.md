# VNT-028 - Many important domain invariants are application-only and lack database-level defense-in-depth.

> **Source of truth:** Current VANTOR archive re-audit

## Classification

- **Severity:** Medium
- **Status:** Strong static finding
- **Confidence:** High
- **Category:** Database integrity

## Location

`backend/app/models/purchase.py, models/contract.py, models/document.py and migrations`

## Evidence

Statuses, currencies and monetary/quantity values are stored as generic strings/integers. The inspected model definitions show few CHECK constraints for status domains, non-negative amounts, or quantity invariants.

## Impact

Direct DB writers, migration mistakes, imports, or future code paths can create states the application was not designed to process.

## Required remediation

Add safe DB CHECK/enum constraints where feasible, validated lookup tables for currencies/statuses where appropriate, and migrations that fail safely against existing bad data. Keep application validation for human-readable errors.

## Required invariant / acceptance

The remediation must preserve tenant isolation, auditability, authorization correctness and deterministic behavior.

## Required tests

Migration against current DB; direct SQL invalid inserts; rollback/repair; ORM path still works.

## Agent rule

Before editing, re-open the cited code and verify that the current source still matches this finding. If code has moved, update the evidence location before proceeding. Do not implement a workaround that leaves two competing code paths enforcing different versions of the same rule.
