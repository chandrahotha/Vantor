# VNT-029 - Synchronous HTTP/Redis work occurs inside async middleware paths.

> **Source of truth:** Current VANTOR archive re-audit

## Classification

- **Severity:** Medium
- **Status:** Verified
- **Confidence:** High
- **Category:** Performance

## Location

`backend/app/core/security.py:46-61; backend/app/core/ratelimit.py:43-82`

## Evidence

JWT JWKS refresh uses `httpx.get()` in synchronous code reached from async request handling. Rate limiting uses synchronous Redis client operations in `async def dispatch`.

## Impact

Slow network/Redis operations can block the event loop and amplify latency under concurrent load.

## Required remediation

Use async HTTP/Redis clients where the call is on the event loop path, or move blocking operations to a worker/thread boundary. Add latency budgets and timeout/circuit-breaker behavior.

## Required invariant / acceptance

The remediation must preserve tenant isolation, auditability, authorization correctness and deterministic behavior.

## Required tests

Load with slow JWKS/Redis; event-loop lag; provider outage; concurrent requests.
