# VNT-030 - Client-provided request IDs are accepted without a strict format/length policy.

> **Source of truth:** Current VANTOR archive re-audit

## Classification

- **Severity:** Medium
- **Status:** Verified
- **Confidence:** High
- **Category:** API hygiene

## Location

`backend/app/core/errors.py:22-28`

## Evidence

`X-Request-ID` is used directly when present and returned to the client. There is no validation or maximum length at this boundary.

## Impact

Log/trace cardinality and header hygiene can be abused with arbitrary identifiers.

## Required remediation

Accept a validated bounded ID (for example UUID/ULID) or ignore invalid client IDs and generate one server-side. Preserve a separate traceparent when applicable.

## Required invariant / acceptance

The remediation must preserve tenant isolation, auditability, authorization correctness and deterministic behavior.

## Required tests

Oversized id; whitespace; unicode; invalid characters; duplicate id; valid UUID.
