# VNT-032 - Rate limiting is tenant-wide, method-wide, and fails open when Redis is unavailable.

> **Source of truth:** Current VANTOR archive re-audit

## Classification

- **Severity:** Medium
- **Status:** Verified
- **Confidence:** High
- **Category:** Abuse prevention

## Location

`backend/app/core/ratelimit.py:43-82`

## Evidence

The key is `rl:{tenant}:{method}:{bucket}` and the limit is chosen only by read/write method. On Redis failure, the request proceeds with `X-RateLimit-Bypass`.

## Impact

High-value endpoints can be abused by one user, and Redis outages remove the control entirely.

## Required remediation

Add hierarchical limits by user, tenant, IP/device where lawful, and route/action cost. Make sensitive controls fail closed or use a local emergency limiter when the central store is unavailable.

## Required invariant / acceptance

The remediation must preserve tenant isolation, auditability, authorization correctness and deterministic behavior.

## Required tests

One noisy user vs same tenant; login/auth endpoint; AI spend; upload abuse; Redis outage; burst handling.
