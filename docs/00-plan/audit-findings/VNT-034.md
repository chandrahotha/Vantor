# VNT-034 - Local Compose exposes sensitive infrastructure with development defaults and no production isolation.

> **Source of truth:** Current VANTOR archive re-audit

## Classification

- **Severity:** High
- **Status:** Verified
- **Confidence:** High
- **Category:** Deployment security

## Location

`docker-compose.yml:1-110`

## Evidence

Compose exposes Postgres 5432, Redis 6379, Keycloak 8080 and optional MinIO/Ollama ports. Keycloak uses `start-dev` and default admin credentials are present in the Compose file. Redis has no password/TLS settings.

## Impact

These settings are acceptable only for an isolated local demo. Reusing them for public deployment creates serious attack surface and credential exposure.

## Required remediation

Separate local and production deployment manifests. In production, keep data services private, use secret-managed credentials, TLS, network policies, non-default admin bootstrap, hardened Keycloak mode, and an ingress layer.

## Required invariant / acceptance

The remediation must preserve tenant isolation, auditability, authorization correctness and deterministic behavior.

## Required tests

Production config linter rejects dev mode/default passwords/public data ports.
