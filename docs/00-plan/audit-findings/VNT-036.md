# VNT-036 — Keycloak realm/client/role bootstrap is not self-contained in the default Compose deployment.

> **Source of truth:** Current VANTOR archive re-audit

## Classification

- **Severity:** High
- **Status:** Verified
- **Confidence:** High
- **Category:** Identity / deployment

## Location

`docker-compose.yml:63-80; .env.example around Keycloak variables`

## Evidence

Keycloak starts but no realm import/provisioning service is declared. The application expects realm/client settings such as `vantor` and `vantor-web`.

## Impact

A fresh environment requires manual identity configuration and is easy to deploy with mismatched redirect URIs, roles, issuer or audience.

## Required remediation

Version identity configuration as code: realm export or provisioning job, clients, roles, service account scopes, redirect URIs, logout URLs, audience, and environment-specific secrets. Add a readiness test that proves token validation end-to-end.

## Required invariant / acceptance

The remediation must preserve tenant isolation, auditability, authorization correctness and deterministic behavior.

## Required tests

Fresh environment from zero; realm bootstrap; role token mapping; key rotation; redirect URI validation.
