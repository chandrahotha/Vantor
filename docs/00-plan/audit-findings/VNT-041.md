# VNT-041 — Dashboard expiry count depends on a stored status updated by a background roll, not a live calculation.

> **Source of truth:** Current VANTOR archive re-audit

## Classification

- **Severity:** Medium
- **Status:** Verified
- **Confidence:** High
- **Category:** Dashboard correctness

## Location

`frontend/app/page.tsx:121-124; backend/app/routers/contracts.py:191-212`

## Evidence

The dashboard explicitly says the “flagged expiring” value reflects stored contract status set by `roll-expiry`, not a live 90-day calculation.

## Impact

A failed or delayed scheduler can make the dashboard stale while appearing healthy.

## Required remediation

Make the attention query authoritative by calculating the date window in the data layer or maintain a reliably scheduled, monitored materialized state with freshness metadata. Show “data as of” and scheduler health.

## Required invariant / acceptance

The remediation must preserve tenant isolation, auditability, authorization correctness and deterministic behavior.

## Required tests

Scheduler stopped; clock moved; contract crosses threshold; dashboard freshness indicator.
